## D16-06 Build–Buy–Partner–Invest Decision Rules

| 상황 | 기본 선택 | 이유 | 예시 Capability |
|---|---|---|---|
| SK온 고유 Recipe·Cell Design·Failure Label이 경쟁력의 핵심 | `BUILD_CORE` + 외부 Tool | 지식·모델의 차별화와 재사용권 보호 | AI Researcher·Yield Causal Model |
| 표준화된 Enterprise Workflow이며 차별화가 낮음 | `BUY_CONFIGURE` | 구축기간·유지보수 절감 | CLM·Supplier Questionnaire·OT Asset Inventory |
| 외부 Sensor/Platform과 내부 도메인 Label이 모두 필요 | `CO_DEVELOP` | 어느 한쪽만으로 성능 확보 불가 | Ultrasound Inspection·Field Failure AI |
| 외부가 핵심 Process/IP를 보유하고 Pilot 이전이 가능 | `LICENSE_TRANSFER` | 내부 생산역량과 외부 기술 결합 | Solid-state Process·Direct Recycling |
| 장기 물량·시장·공급망을 함께 만들어야 함 | `STRATEGIC_PARTNER` | 단기 SaaS 구매로 해결 불가 | Recycled Material Loop·Battery Passport Network |
| 기술 Option은 크지만 성숙도·공급사 지속성 불확실 | `INVEST_OPTION` | 정보권·우선권과 Downside 분리 | Emerging Materials/Process Startup |
| 경쟁사와 이해상충·배타성·IP 위험이 큼 | `OBSERVE_BENCHMARK` | Capability는 학습하되 직접접근 제한 | 경쟁 Cell Architecture Platform |
| Hard Gate 위반 | `NO_GO` | 성과와 무관하게 수용 불가 | Safety Bypass·무제한 Data 학습 |

의사결정은 회사 단위가 아니라 `Provider × Solution × Site × Use Case × Contract Version` 단위로 한다. 같은 Provider도 DPP에는 `BUY_CONFIGURE`, 핵심 Cell Design에는 `NO_GO`가 될 수 있다.

### 7. 사실 상태와 계약 상태

#### 7.1 근거 상태

| 상태 | 사용 조건 |
|---|---|
| `CONFIRMED_PRIMARY` | SK온·상대 회사·정부·규제기관의 원문으로 직접 확인 |
| `CONFIRMED_MULTI` | 서로 독립적인 신뢰 출처 2개 이상이 일치 |
| `REPORTED` | 신뢰 가능한 단일 보도·공시가 있으나 당사자 원문 미확보 |
| `INDICATED` | MOU, 의향서, 검토·협상·잠재 공급 등 비구속 단계 |
| `INFERRED` | 공개 사실의 결합으로 도출했으나 직접 확인되지 않음 |
| `HYPOTHESIS` | 조사·O/I 발굴용 가설. 사실 그래프에는 투입 금지 |
| `CONFLICTED` | 출처 간 내용이 충돌하여 해소가 필요 |

#### 7.2 계약·프로젝트 상태

`ANNOUNCED` · `MOU_NON_BINDING` · `FRAMEWORK` · `BINDING_SIGNED` · `ACTIVE` · `EXPIRED` · `COMPLETED` · `SUSPENDED` · `CANCELLED` · `UNKNOWN`

#### 7.3 반드시 지킬 판정 규칙

- MOU는 공급계약이 아니다. `MOU_NON_BINDING`으로 분리한다.
- 계약기간이 2025년에 끝났다면 2026년 현재 공급사로 자동 승계하지 않는다.
- 광산국과 정련국, 소재 생산국을 하나의 ‘원산지’로 합치지 않는다.
- 모회사 국적만으로 시설 또는 자회사의 PFE 해당 여부를 단정하지 않는다.
- ‘북미용 공급 검토’와 ‘특정 미국 공장 납품 확정’을 구분한다.
- 배터리에 일반적으로 필요한 소재라는 이유만으로 SK온의 실제 구매관계를 만들지 않는다.
- 공급물량과 상대 회사 생산능력을 혼동하지 않는다.
- 고객·제품·공장 배정이 비공개이면 `UNKNOWN`을 유지한다.

### 8. 시점 관리

모든 사실 레코드는 아래 네 시점을 분리한다.

- `announcement_date`: 발표일
- `valid_from`: 계약·규정·관계 효력 시작일
- `valid_to`: 종료일 또는 예상 종료일
- `as_of_date`: 해당 사실을 검증한 날짜

동일 관계가 갱신되면 기존 레코드를 덮어쓰지 않고 새 버전을 만든다. ‘현재 공급관계’ 질의는 `status=ACTIVE`이면서 `valid_from ≤ query_date < valid_to`인 레코드만 반환한다.
